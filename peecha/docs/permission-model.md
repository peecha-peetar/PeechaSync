# مدل سیستم دسترسی پیچا

اسکیمای مرتبط: `peecha/db/schema/002_security_rbac.sql`

## اجزای مدل

- **کاربر (User)** → می‌تواند در چند **شرکت (Company)** عضو باشد.
- در هر شرکت، کاربر یک یا چند **نقش (Role)** دارد (`sec.UserRoles`).
- هر نقش مجموعه‌ای از دسترسی‌ها دارد در سه سطح:
  1. **منو** (`sec.RoleMenuPermissions`) — آیا این آیتم منو برای این نقش نمایش داده می‌شود؟
  2. **فرم + اکشن** (`sec.RoleFormPermissions`) — آیا نقش اجازه‌ی VIEW / CREATE / EDIT / DELETE / PRINT / EXPORT / APPROVE روی این فرم را دارد؟
  3. **فیلد** (`sec.RoleFieldPermissions`) — محدودسازی اضافه روی یک فیلد خاص از یک فرم (Hidden یا ReadOnly)، فقط برای سخت‌گیرتر کردن نسبت به سطح فرم.

## قوانین پیش‌فرض

- **Deny by default**: اگر ردیفی برای یک (نقش، فرم، اکشن) وجود نداشته باشد، دسترسی وجود ندارد.
- **فیلد از فرم پیروی می‌کند**: اگر فرم اجازه‌ی EDIT دارد و ردیفی در `RoleFieldPermissions` برای آن فیلد نباشد، فیلد قابل‌ویرایش است. فیلد هرگز نمی‌تواند بیشتر از سطح فرم دسترسی بدهد — فقط می‌تواند محدودترش کند.
- **`IsSuperAdmin`** در `sec.Users` تمام بررسی‌های بالا را دور می‌زند (برای نگهداری سیستم، نه استفاده‌ی روزمره).
- **تاریخچه‌ی خودکار**: چهار جدول تخصیص/دسترسی (`UserRoles`, `RoleMenuPermissions`, `RoleFormPermissions`, `RoleFieldPermissions`) به‌صورت *System-Versioned Temporal Table* (قابلیت SQL Server 2016) ساخته شده‌اند؛ یعنی هر تغییری در دسترسی‌ها با `FOR SYSTEM_TIME` قابل حسابرسی است، بدون نیاز به کد اضافه در برنامه.

## یک نکته‌ی طراحی که نیاز به تایید شما دارد

وقتی کاربری **چند نقش همزمان** در یک شرکت داشته باشد، دو مدل رایج برای ترکیب دسترسی‌ها وجود دارد:

1. **اجتماع/Union (پیش‌فرض فعلی طراحی)**: اگر *هر یک* از نقش‌های کاربر اجازه‌ای را بدهد، کاربر آن را دارد. این روش استاندارد اکثر ERPها (مثل Dynamics, Odoo) است و برای دسترسی‌های منو/فرم منطقی است.
2. **محدودترین‌برنده برای فیلدهای حساس**: برای فیلدهایی مثل حقوق یا بهای تمام‌شده، معمولاً منطقی‌تر است که اگر *حتی یک نقش* آن فیلد را Hidden کرده، فیلد مخفی بماند — حتی اگر نقش دیگر اجازه‌ی ویرایش کامل فرم را داده باشد.

فعلاً منطق تصمیم‌گیری در دیتابیس پیاده نشده (این کار در لایه‌ی اپلیکیشن هنگام محاسبه‌ی «دسترسی مؤثر» انجام می‌شود). لطفاً تایید کنید:
**آیا برای فیلدهای حساس، «محدودترین نقش برنده است» را به‌عنوان قاعده‌ی پیش‌فرض بپذیریم؟** (پیشنهاد من: بله)
